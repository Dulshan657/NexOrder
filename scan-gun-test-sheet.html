Scan gun test sheet

Code 128, rendered by the app's own encoder (supabase/functions/_shared/labels/code128.ts) from live codes in the dev database. A successful scan therefore proves the encoder, not just the gun.

Print at 100%. In the print dialog set Scale to 100% or "Actual size" — never "Fit to page", which silently changes the bar width and invalidates the calibration ladder at the bottom. Plain white paper, and avoid draft/toner-save mode: it thins the bars.

1 · Bins that hold stock

Scan one of these on the Stocktake screen. Each already has stock in it, so the count sheet will have lines to show. The grey line under each code is the location kind and how many SKUs it holds.

2 · Warehouse roots

A site root is the legal destination for a receipt. Scanning one on Receive Stock switches the destination. Scanning a bin there is refused on purpose — stock reaches a bin through Putaway, never through a receipt.

3 · Pallets and cartons

Handling units. Scan one on the Putaway finder — it should jump straight to the queued line for that plate, or say that nothing is waiting on it.

4 · Product SKUs

Our own identifier, and what the app prints on a product label. Scan on Receive Stock to add a line.

5 · Supplier barcodes (EAN-13 / UPC-A)

Seeded by npm run seed:barcodes:dev. These exercise barcodeVariants — the GTIN folding that makes a 12-digit UPC-A and its 13-digit EAN-13 spelling the same item.

6 · The same item, spelled three ways

All three of these should resolve to one product. This is the single most intricate branch in the resolver and it has never been tested with a real beam. If any one of them resolves to a different product, or to nothing, that is a real bug.

7 · Codes that should FAIL

A test that only proves the happy path proves very little. Each of these should be refused with a specific sentence, not a silent no-op and not a generic error.

8 · Calibration ladder — find your gun's limit

The same code (WIEDEMO-Z1-AR-R1-B15-L1, the longest on site) at each of the six widths in CALIBRATION_WIDTHS_MM. Scan from the top down and note the narrowest one that reads first time, at the distance you actually work at. That figure is what to choose label stock against — lib/labels/sizing.ts refuses anything below 0.25 mm outright, and wants 0.33 mm at arm's length and 1.0 mm down an aisle.
