# Scan gun test guide

How to prove the barcode implementation with a real scanner, end to end.

**Target:** the demo — <https://nexorder.vercel.app> (Supabase `uqvekvavkjjurpqtovbq`).
**Never run this against `nexorder.com.au`.** That is Amadiya's live database; a
stocktake there posts a real variance against a paying client's stock.

**Device:** a desktop or laptop PC with a USB or Bluetooth keyboard-wedge gun.

Work through the tiers in order. Each one only makes sense if the one before it
passed — there is no point debugging a workflow when the gun is not typing.

---

## 0 · Before you touch the app

### 0.1 Configure the gun

Almost every "scanning doesn't work" report is one of these three settings.
They are changed by scanning configuration barcodes out of the gun's own manual.

| Setting | What it must be | Why |
|---|---|---|
| **Interface / mode** | **USB HID keyboard** (sometimes "keyboard wedge" or "HID KBW") | In "USB COM"/serial mode the browser sees nothing at all. |
| **Suffix / terminator** | **CR** (Enter) — **Tab** also works now | Enter is the usual factory default. A gun with *no* suffix now works too, via a 120 ms quiet-time flush, but it is the slowest of the three. |
| **Inter-character delay** | **0 ms** (or the lowest available) | ⚠️ **This one will silently defeat everything.** The app tells a gun from a person by how fast the characters arrive — the threshold is 50 ms per character (`WEDGE_MAX_INTERKEY_MS`). A gun configured with a 50 ms delay looks exactly like a human typist and will be ignored by the stray-scan capture. Symptoms: scanning into a focused box works, scanning anywhere else does nothing. |

Also worth setting: **Caps Lock off** on the PC. A gun that sends Shift for
uppercase plus an OS Caps Lock produces lowercase. Harmless here — every code is
folded through `normalizeScan`, which upper-cases — but it makes the on-screen
text look wrong while you are debugging something else.

### 0.2 Prove the gun before blaming the app

Open Notepad. Scan any barcode.

- **Characters appear, then the cursor jumps to a new line** → CR suffix. Ideal.
- **Characters appear, cursor jumps sideways** → Tab suffix. Fine.
- **Characters appear, cursor stays put** → no suffix. Works, 120 ms slower.
- **Nothing appears** → the gun is not in HID keyboard mode. Fix §0.1 before
  going any further.
- **Characters appear one at a time, visibly** → the inter-character delay is
  too high. Fix it or the stray-scan capture will never fire.

### 0.3 Print the test sheet

```bash
npm run seed:barcodes:dev     # gives 40 demo products real EAN-13 / UPC-A codes
npm run scan:sheet            # writes scan-gun-test-sheet.html at the repo root
```

Open `scan-gun-test-sheet.html` in a browser and print it.

> **Print at 100% / "Actual size". Never "Fit to page"** — that silently rescales
> the bars and makes the calibration ladder in §5 meaningless. Plain white paper,
> and turn off draft/toner-save, which thins the bars.

The sheet is drawn by the app's **own** Code 128 encoder
(`supabase/functions/_shared/labels/code128.ts`), from codes read live out of the
demo database. That is deliberate: a sheet generated by some website would scan
perfectly even if our encoder were broken, and would prove nothing.

### 0.4 Log in

<https://nexorder.vercel.app> → click the **Admin** chip in the demo-accounts
panel (`alice@nexorder.com.au`). The password is `SEED_USER_PASSWORD` in
`.env.dev.local`.

> **Do not test as the Warehouse role on this demo.** Both Warehouse accounts
> have `home_warehouse_id = NULL`, and `StocktakePage` gates its Post button on
> that field matching the selected site. Everything will look fine until the very
> last click, which will be disabled with no explanation. Admin has no such gate.

## 1 · Tier 1 — does a scan reach the app at all?

Go to **Stocktake** (left nav). The cursor should already be in the "Scan a bin
label" box.

1. Scan **`MAIN`** from section 1 of the sheet.
   Expect: the code appears, the count sheet for the Main Warehouse root opens,
   and you hear a **short high blip**.
2. Go back, click somewhere empty on the page (so nothing is focused), and scan
   **`MAIN-F01-R05`**.
   Expect: **the same thing**. This is the stray-scan capture — before this work
   the characters went nowhere and there was no indication at all.

If step 1 works and step 2 does not, go back to §0.1 and check the
inter-character delay.

**Sound.** Two tones, deliberately different in kind, not just pitch:

| Tone | Means |
|---|---|
| Short, high, single blip | The app **accepted** the code |
| Low, buzzing, falling, two notes | The app **refused** it |

The gun's own beep means "I decoded a barcode" and sounds identical whether the
bin was right or wrong. Listen for the app's tone, not the gun's.

> First scan after a page load may be **silent** — browsers refuse to start audio
> until the user has interacted with the page. The coloured border flash still
> fires. From the second scan on, sound works.

## 2 · Tier 2 — does every kind of code resolve?

Still on **Stocktake**, scan one of each and check the message. You are testing
that the app can *tell the three namespaces apart*.

| Scan (sheet §) | Expected result |
|---|---|
| A bin, e.g. `MAIN-F01-R05` (§1) | Opens the count sheet. **Accept** tone. |
| A pallet, e.g. `HU-000242` (§3) | *"That code names a product or a pallet. Scan a bin label instead."* **Reject** tone. |
| A SKU, e.g. `AYM-COC-001` (§4) | Same message. **Reject** tone. |
| `NOT-A-REAL-CODE` (§7) | *"No location in this warehouse matches NOT-A-REAL-CODE."* |
| A zone/aisle code, if you have one | *"… is a ZONE — a container, not a place stock sits."* |

**The important one — GTIN folding (sheet §6).** Three barcodes, three different
lengths, all the same number:

```
074250000042     ← 12-digit UPC-A, which is what the database stores
0074250000042    ← 13-digit EAN-13 spelling
00074250000042   ← 14-digit GTIN spelling
```

Go to **Receive Stock**, pick any supplier, and scan **all three** into the
product box. Each must add a line for **the same product** (`AYM-COC-004`).

This is the single most intricate branch in the resolver
(`barcodeVariants` in `_shared/scanNormalize.ts`) and until this sheet existed it
had **never been exercised by a real scanner**, because no demo product had a
barcode at all. If any of the three resolves to a *different* product, or to
nothing, that is a genuine bug — write down which one.

## 3 · Tier 3 — the three workflows

### 3.1 Stocktake

**Nav:** Stocktake. **Undo:** re-count back to the original number.

1. Scan a bin from sheet §1 — use one with 2+ SKUs so there is something to see.
2. **Write down the current on-hand figure for every line before you touch
   anything.** This is your undo.
3. Type a different number into one line. Leave the others blank.
   - **Blank is not zero.** A line nobody typed into is untouched. A write-off
     must be typed as an explicit `0`.
4. Post the count.
5. Check **Stock** — the figure should have moved, and the movement ledger should
   show a `stocktake_variance`.
6. **Undo:** scan the same bin again, type the original figure, post.

Worth trying deliberately: enter a number *lower* than the bin's available stock
allows. The line should be refused **on its own**, with the other lines still
posting — a half-applied count is worse than none.

### 3.2 Receive Stock

**Nav:** Receiving. **Undo:** adjust the received quantity back down.

1. Pick a supplier.
2. **Scan a site root** from sheet §2 (e.g. `WIE-DEMO`) → the destination
   changes. Accept tone.
3. **Scan a bin** from sheet §1 → refused, with:
   *"… is a bin. Receipts land at the site — Putaway moves the stock to a bin
   afterwards."* This is correct, not a bug: `receive-stock` takes a warehouse,
   and passing a bin would also mis-stamp the pallet's `warehouse_id`.
4. **Scan a carton barcode** from sheet §5 → adds a receipt line. Accept tone.
5. Set a quantity. In the **Batch barcode** cell on that line, scan another code
   from §5 — it should land normalised (upper-case, no stray characters).
6. Receive it.
7. Check **Putaway** — the receipt should have raised a putaway recommendation,
   and a new `HU-0002xx` plate should exist.
8. **Undo:** Stock → adjust that product back down by what you received.

### 3.3 Replenishment

⚠️ **There are currently 0 open replenishment tasks on the demo, so there is
nothing to walk until you create one.** Setup first:

1. **Replenishment → Setup** (`?subtab=setup`), Admin or Manager only.
2. Find a product that has stock in a **reserve/bulk** bin and a **pick-zone**
   home bin. The grid ranks by demand and shows the home bin.
3. Set **min** and **max** (in packs) and **arm** the row — arming is what makes
   it count; saving figures alone does nothing.
4. Save.
5. Back on the queue, run **Detect**. If no task appears, the queue tells you
   why — `source_reserved`, `no_source`, `slot_full`. Those are real answers, not
   errors: replenishment is sized from **available** stock, never `on_hand`, so
   fully-allocated reserve stock correctly raises nothing.

Then walk it:

1. Assign the task, open the walk.
2. **Scan the source bin.** A *different* bin is **accepted** and recorded — the
   assigned bay is often empty and pulling from the next one along is the right
   call. Amber banner naming both bins. Accept tone.
3. **Scan the plate.** A wrong plate is refused and **the field now clears**
   (it used to keep the bad value, so the next scan appended to it).
4. Enter the quantity.
5. **Scan the destination.** Scan a *wrong* bin on purpose first:
   - Expect **refusal**, reject tone, field cleared, Confirm disabled.
   - This asymmetry is the whole design. A wrong source is recoverable; a wrong
     destination leaves the short pick slot exactly as short while reporting the
     work as done.
6. Scan the right destination, confirm.
7. **Undo:** transfer the stock back from the pick slot to the reserve bin.

## 4 · Tier 4 — the real production path

Everything above used a plain-paper sheet. This is the path that actually puts
stickers on racking.

1. **Settings → Warehouse → Print labels.**
2. Print the **calibration sheet** first ("Before a labelling pass"). It renders
   the site's longest code at six bar widths, and it exists precisely so it can
   be scanned with a real gun. Nobody has ever done this.
3. Generate a **location** run for a published layout. Check that:
   - the stock/size wizard recommends a sheet, and explains its reasoning;
   - a run it considers too small is **refused outright**, naming the offending
     codes, before any PDF is produced (`refuseRun`, ISO floor 0.25 mm);
   - the PDF downloads (it is downloaded, never opened in a tab — a signed URL
     obtained after an `await` is outside the click gesture and gets blocked).
4. Print on real Avery stock at 100% and scan those.

## 5 · The calibration ladder — find your gun's real limit

Sheet §8 is the same code at 0.25, 0.30, 0.35, 0.43, 0.50 and 0.55 mm per module.

Scan from the top down, **at the distance you actually work at**, and note the
narrowest one that reads **first time, every time**. Not "eventually".

Then compare against `lib/labels/sizing.ts`:

| Distance | Needs |
|---|---|
| Arm's length | 0.33 mm |
| Across a pallet | 0.50 mm |
| Down an aisle | 1.00 mm |
| **Absolute ISO floor — refused below this** | **0.25 mm** |

If your gun cannot manage 0.33 mm on plain paper, that is expected — a laser
printer's toner spread is worse than the label printer these are designed for.
Re-check on real label stock before drawing conclusions.

## 7 · When something fails — what it means

| Symptom | Almost certainly |
|---|---|
| Nothing happens anywhere, Notepad included | Gun not in USB HID keyboard mode (§0.1) |
| Works in a focused box, dead everywhere else | **Inter-character delay > 50 ms** (§0.1). The single most likely cause. |
| The code appears but nothing commits | Gun has no suffix and the 120 ms flush is being interrupted — or the suffix is something exotic. Set it to CR. |
| Focus jumps to another field mid-scan | Tab suffix landing on a surface where the run did not qualify as machine-speed. Check the delay again. |
| Last character missing, or an extra one | Gun's own prefix/suffix settings. `normalizeScan` strips control characters, not stray printable ones. |
| A valid label reads as "no such location" | Was a real bug in `BinPickerSheet` / `ReleaseQuarantineModal` — both compared raw strings instead of folding. Fixed. If you still see it, capture the exact code. |
| Two different products behind one barcode | Now reported as an **ambiguity** and you get asked. It used to silently pick one. |
| No sound at all | Muted, or the very first scan after a page load (§1). The border flash still fires. |
| Scan lands in a quantity box | Known and accepted: the global capture stands down whenever focus is in *any* input, so it cannot corrupt typing. Click the scan field, or just scan again. |

## 8 · What this exercises, for the record

- `lib/scan/wedgeBuffer.ts` — the gun-vs-human timing machine (`__tests__/wedgeBuffer.test.ts`)
- `lib/scan/useWedgeScanner.ts` — stray-scan capture and its stand-down rule
- `lib/scan/resolveScan.ts` — the three namespaces and ambiguity reporting
- `_shared/scanNormalize.ts` — folding and GTIN variants, shared by both runtimes
- `_shared/labels/code128.ts` — the encoder, proven by the sheet itself
- `_shared/labels/sizing.ts` — the ISO floor and the calibration widths
- `_shared/pickScanCheck.ts` / `putawayScanCheck.ts` / `replenScanCheck.ts` — the
  three deliberately asymmetric validators
